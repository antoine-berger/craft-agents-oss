# Native Craft Ship

This service reuses the existing Tasks board, `createTaskFromSpec`, child sessions, `TaskRunner`, node outputs, persisted run logs and project/worktree inheritance. It introduces no external daemon, second hub, CLI, copied Conductor DB, or Mac path. Resource inputs are under `apps/electron/resources/portable-config/`; installation/import belongs to the backed-up host deployment.

## Host wiring

- Export DTOs from `packages/shared/src/protocol/ship-workflow.ts`; map the six `ship:*` channels and ElectronAPI methods described by `ShipWorkflowAPI`. Channels run on the authenticated workspace server.
- Register `registerShipWorkflowHandlers(server,deps,{confirmShipApproval})`. The callback must obtain fresh interactive human confirmation from the desktop for the supplied workflow/revision/planHash/head and return false on cancellation, disconnect or expiry. With no callback approval fails closed. Do not expose approval as an agent tool or infer it from messages. The server re-reads state/artifacts/head after the dialog.
- Put `ShipWorkflowPanel({workspaceId,sessionId,api})` on the existing session details/tasks surface. It does not poll. Attention can read `findShipState(workspaceRoot,sessionId)` / `getBySession()` with no model or transition; `status`, `phase`, `reasons` and `gates` are concise signals.
- `parseShipCommand()` recognizes only an exact `/ship`, or `/ship-plan <issue>`/canonical Linear URL. Intercept after the session's native repository/worktree preparation. StartPlan binds the invoking session's project. Resume resolves by current session; never auto-run a workflow from a question/ordinary mention. Skill-picker `[skill:ship]` is descriptive and must not fake missing native controls.
- Generic `tasks:run` must refuse `ship-*` slugs using `assertNotGenericShipRun(slug,workspaceRoot)` (ordinary prefixed task names without native state remain supported); native Ship dispatch alone controls stages. Apply `shipSessionToolDenial(workspaceRoot,managedIdentity,toolName,input)` at the actual pre-tool boundary for Ship child sessions (taskSlug/taskNodeId identify ownership), in addition to normal permission checks. It blocks merge/queue/auto-merge, non-draft creation, agent-side ready and reviewer writes. The server's narrowly scoped `gh pr ready` checks both gates, current local head, remote PR head and artifact hash first.
- No workflow is launched at registration/app startup. Start requires the user's explicit action. Native Task execution is resumable; `TaskRunner.resume(...,{verifyOnComplete:false})` preserves deterministic Ship verification after restart instead of asking the pilot for a free-form verdict.

## State and limits

`tasks/<slug>/ship/state.json` is atomically replaced, with revisioned events in `events.jsonl`; plan files are whitelisted under `ship/plan/`, size-bounded and hashed. The server serializes operations. Native Task outputs and node/session attribution, exact HEAD and artifact hash are required. No client-supplied reviewer verdict API exists. A failed G1 reaches human override only after two rounds; changed plans invalidate stale approvals. Build/review/E2E repair attempts and explicit feedback rounds are bounded. Models are selected only from configured available Craft connections; absence blocks instead of invoking a nonexistent Mac binary or changing credentials.

GitHub is read through the existing authenticated `gh` CLI. Missing/partial evidence is blocked, never called green. GitHub Enterprise and more than 100 review threads require a future adapter/manual handling. No merge API is present. Real Sapiom/Sapiom-js runs are blocked by the user's current read-only rule. No production write, real workflow or deployment is performed while implementing/testing this service.

Native Ship parent/children explicitly use `worktree: none` with the owning session’s resolved cwd; unrelated Tasks retain their previous worktree policy. The complete tool helper validates persisted phase, permitted role, native run/session attribution, current artifact hash and human go. Pilot conversation tools remain read-only before go and while a native worker is active. Planner writes are restricted to the six artifact files. Reviewer/E2E evidence and ready require a clean committed tree. Native stage/control files are server-owned.
